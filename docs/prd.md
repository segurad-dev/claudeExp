# 01. Product Requirements Document

## 1. Контекст и проблема

Люди, которые регулярно сдают анализы (хронические заболевания, профилактика, планирование беременности, тренировочный цикл, наблюдение за дефицитами), сталкиваются с одной и той же проблемой: результаты хранятся разрозненно — бумажные бланки, PDF в e-mail, фото в галерее телефона, выписки в мессенджерах. Даже если всё это лежит в одной папке, видеть **динамику конкретного показателя во времени** невозможно без ручного выписывания в таблицу.

Клинические системы (МИС) закрыты для пациентов. Лабораторные ЛК хранят историю только своих анализов, не объединяя данные из разных лабораторий. Универсальных персональных хранилищ, которые работают на своём сервере и не отдают медицинские данные в чужое облако — единицы.

## 2. Цели проекта

### 2.1. Продуктовые цели

1. Дать пользователю единое место, в котором хранится **вся история его анализов**, независимо от лаборатории.
2. Показывать **динамику** каждого показателя во времени — это отвечает на главный вопрос пациента «у меня становится лучше или хуже?».
3. Отображать значения относительно **референсного диапазона** — чтобы мгновенно видеть отклонения от нормы.
4. Сохранять **контекст** замера — симптомы, события, приём лекарств — через свободную заметку и прикреплённые файлы.
5. Давать возможность **редактировать и удалять** записи — это персональные данные пользователя, и он должен иметь полный контроль.
6. Позволять **экспортировать** данные: в JSON/CSV для бэкапа и в PDF-отчёт для показа врачу.

### 2.2. Нефункциональные цели

1. **Приватность**: данные остаются на инфраструктуре пользователя. Никакой телеметрии по умолчанию. Self-hostable через Docker.
2. **Простота запуска**: от `git clone` до работающего приложения на локальной машине — не более 5 минут.
3. **Простота эксплуатации**: одна команда `docker compose up -d` для production. Автоматический HTTPS. Автоматические бэкапы опционально.
4. **Надёжность**: потеря данных недопустима. Бэкапы, транзакции, валидация на обоих концах.
5. **Долговечность**: выбор зрелых технологий, которые будут поддерживаться в горизонте 5+ лет.

## 3. Целевая аудитория

### 3.1. Основной пользователь

- Взрослый человек, самостоятельно следящий за своим здоровьем.
- Регулярно сдаёт анализы (хотя бы раз в 3–6 месяцев).
- Технически грамотный: может настроить домашний сервер или воспользоваться готовым Docker-образом на VPS.
- Ценит приватность медицинских данных — не готов загружать их в облачные сервисы без контроля.
- Владеет компьютером и смартфоном; чаще заходит с телефона.

### 3.2. Вторичный пользователь (близкие)

- Жена/муж, родители, взрослые дети основного пользователя.
- Имеют собственный аккаунт с изолированными данными.
- Чаще используют приложение с телефона, могут быть менее технически подкованы.
- Не занимаются администрированием, им нужен готовый рабочий сервис.

### 3.3. Не целевая аудитория (MVP)

- Врачи, медицинские центры, клиники (приложение не предназначено для профессионального использования).
- Люди, не готовые вводить данные вручную (для них нужен OCR — v2).
- Массовая публичная аудитория (MVP не предусматривает публичной регистрации с лимитами и модерацией).

## 4. Scope MVP

### 4.1. Функциональность в MVP

**Аутентификация и профиль**
- Регистрация по e-mail + паролю.
- Вход/выход, session-based auth.
- Управление профилем: имя, пол, дата рождения (нужны для расчёта референсов).
- Смена пароля.

**Справочник показателей**
- Предзагруженный каталог ~40–60 типовых анализов (ОАК, биохимия, гормоны, витамины, липидный профиль) с единицами и дефолтными референсами.
- Возможность добавить пользовательский показатель.
- Возможность переопределить референс для конкретного показателя «для себя» (например, если рекомендации врача отличаются).

**Ввод замеров**
- Создание замера: дата, заметка, произвольное число значений (показатель → число → единица).
- Поиск/автокомплит показателя при вводе.
- Прикрепление файлов (PDF, JPG, PNG, HEIC) к замеру.
- Редактирование замера и значений.
- Удаление замера (с каскадным удалением вложений и значений).

**Просмотр и аналитика**
- Список всех замеров с фильтрацией по дате и показателю.
- Детальная карточка замера: все значения, флаги отклонений, заметка, вложения, превью файлов.
- График динамики одного показателя во времени с референсной полосой.
- Режим наложения нескольких показателей с нормализацией (значения в % от середины нормы, референс — полоса вокруг 100%).
- Клик по точке на графике → карточка соответствующего замера.

**Экспорт**
- Полный бэкап аккаунта в JSON (с метаданными) + ZIP со всеми вложениями.
- Экспорт выбранного периода в CSV.
- PDF-отчёт с таблицей значений, графиками и заметками за выбранный период.

**Операции**
- Docker Compose развёртывание (web + api + db + caddy).
- Миграции Prisma.
- Логи через stdout.

### 4.2. Out-of-scope MVP

Следующее **не входит** в MVP и отложено на будущие версии:

- OCR/парсинг PDF и фото бланков автоматически (v2).
- Журнал симптомов как отдельная сущность (v2).
- Журнал приёма лекарств с графиком-полосой (v2).
- Теги и категории событий (v2).
- Шеринг выбранных замеров по read-only ссылке (v2).
- Нативные мобильные приложения iOS/Android (v3, возможно, через Capacitor).
- Несколько «подопечных» профилей под одним аккаунтом — для отслеживания здоровья ребёнка/пожилого родственника (v2).
- Импорт из популярных ЛК лабораторий (Helix, Инвитро, KDL) — требует индивидуального парсинга и юридической проработки (v3).
- Уведомления и напоминания о пересдаче анализов (v2).
- Интеграция с wearables (шаги, пульс) (out of scope полностью).
- AI-интерпретация результатов (out of scope — этика и ответственность).
- Двухфакторная аутентификация (v1.0).
- OAuth-вход через Google/Apple (v1.0).

## 5. Нефункциональные требования

### 5.1. Приватность и безопасность

- Все данные хранятся только на инфраструктуре пользователя. Приложение не делает исходящих запросов наружу по умолчанию.
- Пароли хранятся только в виде bcrypt-хэша (cost factor ≥ 12).
- Session ID — криптостойкий random (≥ 128 бит энтропии), в httpOnly + Secure + SameSite=Strict cookie.
- CSRF-защита для всех небезопасных методов (double-submit cookie или Origin-header check).
- Все эндпоинты, кроме `/auth/login` и `/auth/register`, требуют активную сессию.
- Загружаемые файлы сохраняются под хэшем содержимого, отдаются только через эндпоинт с проверкой принадлежности пользователю.
- Content Security Policy ограничивает источники скриптов и стилей.
- HTTPS обязателен в production (Caddy с Let's Encrypt).
- Логи не должны содержать паролей, session ID, содержимого замеров.

### 5.2. Производительность

- Целевой TTI (Time to Interactive) на первом экране — ≤ 2 секунды на 4G.
- API отвечает за ≤ 200 мс для p95 на типовой выборке (до 1000 замеров на пользователя).
- Список замеров пагинируется (по 50 на страницу).
- График строится за ≤ 500 мс для 500 точек.
- Размер загружаемого файла ограничен 10 МБ. Общий лимит хранилища на пользователя — 1 ГБ (конфигурируемо).

### 5.3. Доступность и UX

- Целевая платформа — мобильный веб (вертикальная вёрстка, большие тач-цели), плюс десктопная адаптация.
- Поддержка клавиатурной навигации по основным флоу.
- Контраст текста — не ниже WCAG AA.
- Язык интерфейса — русский. Строки вынесены в словари для будущей i18n.
- Темы — светлая и тёмная, с переключателем. По умолчанию — по настройке ОС.

### 5.4. Надёжность

- Все мутации — в транзакциях БД.
- Валидация на бэке на всех входных данных (Zod).
- На фронте — оптимистические обновления с откатом при ошибке.
- Бэкапы БД — ежедневно через cron в контейнере (опционально, включается переменной окружения).
- Восстановление из бэкапа — документированная процедура в [08_OPERATIONS.md](./08_OPERATIONS.md).

### 5.5. Совместимость

- Браузеры: последние 2 версии Chrome, Safari, Firefox, Edge. iOS Safari 15+, Android Chrome 100+.
- Сервер: Docker ≥ 24, Docker Compose ≥ 2.20. Альтернативно — Node 20+ и Postgres 15+ на bare metal.

### 5.6. Лицензия и юридические ограничения

- Приложение распространяется под свободной лицензией (MIT или AGPL — определить).
- Приложение — **не медицинский прибор**. В UI явное предупреждение: «Информация не заменяет консультацию врача».
- Пользователь принимает ответственность за корректность вводимых данных.
- Для self-hosted версии ответственность за защиту данных несёт оператор сервера.

## 6. Критерии успеха MVP

MVP считается готовым к ежедневному использованию, когда:

1. Пользователь может зарегистрироваться, войти, выйти — без ошибок.
2. Пользователь может внести замер с 5+ показателями и прикрепить 2+ файла за ≤ 2 минуты.
3. На графике корректно отображается динамика любого показателя с референсной полосой, соответствующей полу и возрасту пользователя.
4. Данные переживают перезапуск контейнеров и восстанавливаются из бэкапа.
5. Экспорт в PDF генерирует читаемый отчёт, который пациент может показать врачу.
6. `docker compose up -d` разворачивает рабочее приложение на чистой машине за ≤ 10 минут (без учёта времени ожидания сертификата Let's Encrypt).
7. Второй пользователь, зарегистрированный в той же инсталляции, видит **только свои** данные — изоляция подтверждена автоматическим тестом.

### 6.1. Метрики качества (для разработчика)

- Покрытие бэкенда тестами ≥ 70% (модели, сервисы, auth).
- Покрытие фронта юнит-тестами ключевых компонентов (форма замера, график).
- E2E smoke-тесты для 3 основных флоу: регистрация/вход, добавление замера, просмотр графика.
- Линтер и форматтер без ошибок в CI.
- Зависимости без известных HIGH/CRITICAL уязвимостей на дату релиза.

## 7. Допущения и риски

### 7.1. Допущения

- Пользователь самостоятельно ведёт данные и умеет вводить числа.
- Типовых референсов из справочника достаточно для 95% случаев; остальные пользователь переопределит вручную.
- Основная частота сдачи анализов — раз в 1–6 месяцев. Интервалы менее 1 дня не ожидаются.
- Один замер = один поход в лабораторию. Если сданы сразу разные панели в один день, пользователь может создать один замер со всеми значениями.

### 7.2. Риски

- **Корректность seed-каталога**. Референсы для некоторых показателей варьируются по лабораториям. Митигация: дать пользователю лёгкий способ переопределить референс; в справочнике указывать источник дефолтных значений.
- **Единицы измерения**. Один показатель может измеряться в разных единицах (глюкоза — ммоль/л vs мг/дл). Митигация: справочник хранит базовую единицу, хранилище — значения в базовой единице, UI делает конвертацию при вводе/показе.
- **Приватность при self-hosting**. Ответственность за шифрование диска, резервное копирование, защиту сервера лежит на пользователе. Митигация: чек-лист в [08_OPERATIONS.md](./08_OPERATIONS.md).
- **Усталость от ручного ввода**. Без OCR ввод 10 показателей из бланка занимает время. Митигация: удобные формы, автокомплит, сохранение последних единиц; OCR запланирован на v2.
- **Юридический статус**. В некоторых юрисдикциях хранение медданных регулируется. Митигация: ясный дисклеймер о персональном использовании; публичные сервисы — out of scope.

## 8. Словарь принятых решений

Ниже — ключевые продуктовые решения, зафиксированные на этапе проектирования, с ссылкой на обсуждение.

| Решение | Выбор | Альтернатива | Обоснование |
| ------- | ----- | ------------ | ----------- |
| Пользователи | Несколько (семья) | Один пользователь | Нужна изоляция данных на уровне userId |
| Деплой | Локально → Docker | Облако | Приватность медданных |
| Формат графика | Одна линия = один показатель, переключение слоёв | Все сразу, панели | Единственный корректный способ показать нормы |
| Справочник | Предзагруженный + пользовательские | Только пользовательские | Быстрый старт, 95% покрытия |
| Референсы | Зависят от пола и возраста | Полный контекст (беременность, лаборатория) | Разумный компромисс сложности и точности |
| OCR в MVP | Нет | Да, LLM-vision | Сильно удорожает MVP, парсинг через LLM — v2 |
| Дополнительные сущности | Только заметки и вложения | Теги, симптомы, лекарства | Держим MVP минимальным |
| Экспорт | JSON/CSV + PDF | Шеринг ссылкой, PNG | PDF для врача — ключевой use case |
| Auth | Session cookies | JWT | Проще и безопаснее для single-server self-hosted |
| API | REST + OpenAPI | tRPC | Свобода в выборе клиентов в будущем |
| ORM | Prisma | Drizzle | Быстрее onboarding, богаче экосистема |
